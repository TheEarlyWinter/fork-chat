# 分叉对话 (Fork Chat)

> **打破传统线性聊天，在无限二维画布上进行多分支发散、多模型横向推导与结论收敛。**

分叉对话是专为 [HanaAgent](https://openhanako.com) 平台打造的二维树状分支对话与思维推导工作台（v2 App）。它将传统大模型对话界面的单向追加流，重构为具备完整逻辑回溯能力的**有向无环图（DAG）交互画布**，专为方案对比推演、假设发散探索与复杂决策归纳而生。

---

## 文档生成与交付（2.0）

对话中让模型生成真实文档：**DOCX / PDF / HTML / Markdown**，中文字体内嵌，不是改后缀的文本。

- 文件卡直接出现在助手消息流中，支持内容预览（沙箱渲染）与另存为（系统保存对话框）
- 产物按调用方身份分区持久化；画布重开、App 更新、宿主重启后仍可访问
- 支持导入用户自备的备份文件为当前画布新产物（标记「用户导入」，不解析内容）
- 身份缺失时明确拒绝并给出可见提示，不静默兜底；模型无法在未生成文件时谎称成功

## 核心设计理念

传统的对话界面通常采用线性追加模型。当用户希望在某个节点探讨替代方案或测试不同假设时，后续的讨论会混入主上下文，造成长上下文维护负担并破坏上下文纯度。

分叉对话将对话结构建模为二维有向无环图：
- **分支独立解耦**：子节点的发散探索保留在各自独立的分支路径上，不反向污染其他平行分支。
- **动态横向对比**：支持在任意节点发起多模型横向对决（Battle），直观横向比对不同模型或不同提示词的推理质量。
- **多前置按需汇聚**：需要综合多个维度的结论时，支持从多个父节点收敛生成综合节点，自动去重并按时序组装完整前置上下文。
- **纯白极简视觉**：采用纯白背景（`#ffffff`）、浅灰边框（`#e4e4e7`）与深灰文字（`#18181b`），去除非必要的视觉装饰与高饱和度配色，聚焦于文本与推导逻辑本身。

## 核心特性

### 1. 2D 拓扑推导画布
- **自由交互与视口平移**：支持平移、无级等比缩放（0.4x ~ 2.2x）、卡片拖拽与以当前指针为锚点的平滑对焦。
- **2D 自由拉伸手柄**：每张卡片右边缘、底边缘及右下角配备拖拽手柄，支持自由调节卡片宽度（340px ~ 720px）与高度（240px ~ 1200px），多行长文阅读自适应适配。
- **自适应视野包裹**：卡片分支或对战生成时，视口引擎自动根据当前缩放矩阵计算安全边距，杜绝卡片飘出可视范围。
- **动态 SVG 贝塞尔连线**：基于拓扑关系的自适应曲率连线；针对反向、重叠与深层嵌套场景进行原位复用（O(V+E) 拓扑渲染）。

### 2. 多模型并发推理与横向对决 (Battle)
- **多模型并行推导**：支持为不同分支节点独立指定不同的 AI 助手身份与思考深度（Reasoning Effort），互不干扰。
- **一键对比推导 (`⑂`)**：在卡片底栏或右侧锚点点击“对比”，唤起多模型对决弹窗，选择 2~4 个不同模型并行推演同一问题，系统自动进行无碰撞纵向排列。
- **原生打字机流式输出**：基于标准 ReadableStream，多卡片并发流式吐字，平滑滚动跟随。
- **心境与结构化标签折叠**：模型输出中的 `<mood>`、`<pulse>`、`<reflect>` 等元思考与心境标签自动归入折叠抽屉，正文区域保持纯净，上下文传递自动剔除冗余标签。

### 3. 多父节点汇聚与综合收敛 (Convergence)
- **多选汇聚**：按住 `Shift` 依次点击两张或多张不同分支的卡片，点击顶栏“汇聚选中卡片”开辟综合节点。
- **拓扑全路径穿透**：系统向上递归遍历所有父节点的祖先分支，精准去重后按严格时序合成上下文，送入模型进行归纳与整合。

### 4. 资料源与混合附件流水线 (Document Pipeline)
- **形态 A：卡片局部附件**：支持向任意对话卡片拖拽或点击回形针添加文档（支持 `.pdf`、`.docx`、`.md`、`.txt`、代码文件等），作为单次追问的参考材料。
- **形态 B：独立资料源根卡片**：直接将文档拖拽至画布空白处，自动解析生成只读「资料源」根卡片，后续所有分析与推导分支均基于该文档开辟。
- **纯 JS 安全解析**：集成轻量化 PDF 解析内核（unpdf / bundled pdf.js），中文排版解析在本地完成。小文件在 App 服务内直接解析；超过 16 MB 或需要云端 OCR 时，经一个只监听回环地址的本地助手进程搬运，避免把大文件塞进宿主消息通道。

### 5. 高效沉浸体验：盖戳、顺藤摸瓜导出、全局搜字与分支折叠
- **卡片状态盖戳标记**：点击卡片右上角状态按钮轮转方案标记——【★ 星标关注】（金边高亮）、【✓ 已采纳】（绿边光晕）、【✗ 已否决】（**整卡半透明置灰 55%**）。复杂推演完毕后，一眼分清各条探索路径的成败结论。
- **顺藤摸瓜整链长文导出 (`⎘`)**：在任意叶子卡片表头点击导出按钮，系统自动顺着拓扑路径回溯祖先分支，精准去重后将所有问答流组装为格式优美的完整 Markdown 思考复盘长文，并一键复制到剪贴板，可直接粘贴到报告、飞书或文档中。
- **全画布搜字瞬移 (`Ctrl+F` / `Cmd+F`)**：随时按下快捷键唤起全画布浮动搜索栏。支持不区分大小写模糊匹配卡片标题、草稿、对话消息及附件名；命中卡片全画布金边高亮，敲击回车视口平滑飞掠居中，支持 `Enter` / `Shift+Enter` 快速穿梭。
- **分支子树一键折叠 (`−` / `+`)**：有后代分支的卡片在表头展示折叠开关，点击即可将该分支下挂的所有子孙卡片与连线收拢隐藏，并在卡片上留下清晰的「已折叠 N 个分支」药丸徽标；点击药丸即可随时一键恢复展开，释放宝贵的画布空间。
- **画布级时光倒流与撤销重做 (`Ctrl+Z` / `Ctrl+Shift+Z`)**：提供最大 30 步高内聚拓扑快照。支持分支开辟、卡片删除、位置拖拽、尺寸拉伸与自动排版的完整回退。具备空输入框智能穿透、模态弹窗保护、流式输出防破坏与输入法防误触四重守卫。

### 6. 极客键盘快捷键与一键自动排版
- **Tab 分叉**：在卡片输入框中直接按下 `Tab`，秒速派生子分支并自动聚焦输入框。
- **Space 抓手平移**：按住空格键即可将鼠标变为抓手，在画布任意位置拖拽平移。
- **方向键拓扑导航**：选中卡片后，使用 `↑` / `↓` 在兄弟节点间切换，`←` 定位父节点，`→` 定位子节点。
- **一键 Auto-Tidy 整理 (`Shift+A`)**：点击顶栏整理按钮或按下快捷键，基于层次布局算法（Layered DAG Layout）自动计算各分支深度并重排卡片位置，保持拓扑清爽整洁。
- **多分支合并总结 (`Shift+M`)**：多选分支后按下快捷键，快速开辟综合总结卡片。

### 7. Hana 本体双向受控桥接 (Session Bridge)
- **消息级 / 会话级单向导入**：
  - 悬停于宿主聊天消息末尾，点击「送到分叉对话」直接作为根节点切入画布。
  - 在宿主会话列表右键选择「导入到分叉对话」，指定叶子分支提取最新上下文。
- **来源引用与本体回溯**：导入的卡片标有「本体导入快照」徽标，支持一键点击「跳回本体」即时跳转至宿主原始聊天。
- **两阶段安全回传发件箱 (Outbox)**：推演获得结论后，通过「回传」功能将成果发回宿主原会话。具备两阶段确认（Prepare → Confirm）与幂等防重机制。

### 8. 选定分支在 Hana 中继续 (Branch Handoff)
- **独立分支无缝交接**：在任意卡片底部点击「在 Hana 中继续」，系统将沿着 DAG 依赖图向上收集该分支完整的祖先问答链路、原文快照引用与生成产物，创建全新的宿主主页（Home）会话。
- **两阶段安全预检**：准备阶段（Prepare）严格校验已保存快照、权限契约、产物一致性与目标 Agent，生成不可变 actionId；用户在对话框中确认（Confirm）后执行原子投递。
- **只读快照与零静默消耗**：交接新会话默认关闭记忆（memoryEnabled: false），以结构化 custom 消息与 `handoff.md` 上下文交付，绝不主动启动模型推理，不消耗多余额度。
- **权限模型兼容的落盘方式**：在 Node `--permission` 运行环境下，交接动作记录与交付文件改用 O_SYNC 独占写入并免除不可用的目录同步；交付阶段崩溃/重启后状态仍以已写入的动作记录为准，但**不承诺突然断电、内核崩溃或目录项丢失后的恢复**。异常中断后请先在目标会话核查已暂存的文件与正文，不要盲目重复确认。
- **交接卡与文件入口**：交接消息在 Chat 中以只读「交接记录」卡展示完整正文与交付文件入口，文件仍属于宿主主页会话（用 `session-file` 预览打开，不伪造原生附件气泡）。预览走 `hana.resources.open`，需要宿主授予只读资源能力 `app/resources.read`；更新到本版本时，装载确认弹窗会要求一并确认这一项（只读，不扩大写入范围）。beta.3 及更早写入的历史消息只要该会话与动作回执（sessionId/entryId/actionId 一致）仍在，重开对应会话即可回放出同一张卡，不需要重新交接。

## 模块化系统架构

为确保长期的代码健壮性与可维护性，前端交互层已从单一大文件解耦为职责清晰的模块化架构：

```text
ui/assets/
├── panel.js                # 主协调控制器：会话生命周期、事件分发与画布状态机
├── panel-viewport.js       # 视口引擎：2D 矩阵变换、指针锚点缩放与自适应包裹计算
├── panel-cards.js          # 卡片视图引擎：卡片纯函数式 DOM 组装与 2D 尺寸限制守卫
├── panel-battle.js         # 对决控制器：横向对比分支算法、输入校验与弹窗交互
├── panel-connectors.js     # 连线引擎：贝塞尔曲线几何计算、反向锚点翻转与原位复用
├── panel-layout.js         # 拓扑排版引擎：多父 DAG 分列对齐与一键 Auto-Tidy 碰撞规避
├── panel-shortcuts.js      # 快捷键系统：Tab 分叉、方向键导航、抓手平移与 IME 输入法防误发
├── fork-session-store.js   # 持久化存储：Web Locks 多窗口并发协调与本地容灾落盘
└── fork-session-controller.js # 会话生命周期状态机与代际隔离防串染
```

## 权限声明与安全边界

本应用在 `manifest.json` 中声明了以下能力，各项权限均严格限定于对应功能：

| 权限标识 (Capability) | 对应功能用途 | 安全说明 |
|---|---|---|
| `app/models.infer` | 驱动画布卡片的大模型推理与流式输出 | 仅在用户主动点击发送或对比时触发推导，绝不后台静默扣额 |
| `app/agents.read` | 读取宿主已配置的助手身份与默认模型 | 仅读取公开元数据，不访问私有系统提示词实现 |
| `app/sessions.read` | 读取本体会话，用于导入、回传与交接回执 | 三处场景：用户主动导入时读取条目树与消息快照；回传本体时列出会话并核对运行状态；打开交接卡后核对回执归属。展示层只投影所需字段，不代表宿主交回的字段仅限于此 |
| `app/sessions.home` | 在 Hana 宿主主页创建公开会话（分支交接） | 仅在用户在分支交接弹窗确认后创建独立主页会话，默认关闭记忆 |
| `app/sessions.manage` | 执行「回传本体」与写入交接正文动作 | 仅在用户于弹窗二次确认后向指定会话发送消息 |
| `app/session.start-turn` | 回传消息后唤醒宿主会话模型生成回答 | 仅在用户在回传对话框里点「确认投递」之后触发；对话框内会明示该动作可能消耗模型额度 |
| `app/session.stage-file` | 将推导内容或产物作为文件交付到宿主会话 | 在分支交接中交付产物文件与 handoff.md 存档；需经用户二次确认 |
| `app/resources.read` | 只读预览交接卡里的宿主会话文件 | Markdown 与文本经宿主后端 `stat`/`read` 取回内容后在卡内渲染，其余类型通过 `resources.open` 的 `session-file` 预览打开；只读，不写入或覆盖任何资源 |
| `app/resources.write` | 将文档产物另存到用户选定的位置 | 仅在用户点击「另存为」后调用 `hana.resources.saveFile`；目标选择、已有文件覆盖确认、冲突与保存回执均由宿主处理。App 自身 `dataDir` 的文件读写不依赖这项授权 |
| `app/runtime.execute` | 启动受控后台助手进程完成大文档解析 | 仅启动应用私有目录内的脚本，不调用任意系统程序 |
| `app/runtime.native` | 允许文档解析助手使用原生运行能力 | 本应用只启动固定的 `runtime/parser.mjs`，并在业务代码里校验上传与结果路径。**这不是宿主的只读目录隔离**：macOS/Linux 下原生运行时可以读取当前系统用户可读的工作区外文件，Windows 使用每次运行的新专用身份，边界以宿主策略为准 |
| `app/runtime.network` | 允许解析助手建立外网连接与服务监听 | 请求的 HTTPS 协议、MinerU 域名白名单与重定向由本应用自行校验（`lib/parser-network.js`）。**原生外网不经过宿主顶层的 `network.allowedHosts` 代理白名单**，不能理解为宿主强制的域名隔离；受宿主清单约束的是 `sdk.network.fetch` 那条通道 |
| `app/ui.clipboard-write` | 画布卡片文本与推导链的一键复制 | 仅由用户点击复制按钮触发 |

## 安装与使用

1. 从 [GitHub Releases](https://github.com/TheEarlyWinter/fork-chat/releases) 下载 **`app-timeline-reverser-版本号.zip`**，不要下载自动生成的 **Source code**；
2. 打开 **HanaAgent** 桌面客户端，进入「扩展管理」，导入 ZIP 并核对、确认权限；升级前先保存当前会话；
3. 安装完成后，在应用导航栏点击 **「分叉对话」**。如仍显示旧版，使用 App 的正式重载入口；
4. 在 Hana 中配置好模型后即可对话，无需自行安装 Node、npm 或项目依赖。该 ZIP 是 Hana App，不是独立桌面程序。

宿主版本须满足 `manifest.json` 的 `minAppVersion`（当前 `1.2.1-beta`），建议使用 **HanaAgent 1.2.1-beta 或更新的兼容版本**。可选云端 OCR 需另配 MinerU；当前原生解析助手存在 `ERR_ACCESS_DENIED` 已知问题，不作为本版已修复功能承诺。

Release 同时提供 `SHA256SUMS`（完整性校验）、`.entry.json`（市场元数据）及 `build-info.json`（构建来源）。普通用户只需安装 ZIP。

### 真实限制与已知边界

- **Custom 文本导入而非原生历史**：受限于宿主扩展能力边界，分支交接在新会话中以单条结构化 custom 消息呈现推导路径与下一步要求，并以 `handoff.md` 和产物附件形式交付完整上下文，而非以原生多轮对话消息逐条伪造注入历史。
- **手动授权入口与宿主全链路实机验收**：`app/sessions.home` 自宿主 **1.1.111-beta** 起可声明，而本应用当前最低要求为 `manifest.json` 的 `minAppVersion`（**1.2.1-beta**），因此在受支持的宿主上该项必然可授予。授权仍需用户在弹窗中明确确认；若宿主未开通该能力，交接准备阶段会给出明确阻断提示，绝不私自降级为应用私有会话。
  - 已实机验收（2.4.0）：交接准备、确认、主页会话创建与文件交付、交接卡渲染、Markdown 文件预览。
  - 使用中观察项，不作为安装阻断：模型承接上下文的效果、目标 Agent 已启用 Skill 的实际调用。

### 本地验证

测试随仓库提供，不依赖任何 npm 包，只需 Node 24 或更新版本：

```bash
node --experimental-vm-modules --test tests/*.test.mjs
```

- `--experimental-vm-modules` 不能省。面板集成测试用 `vm.SourceTextModule` 加载 UI 模块，缺这个标志会整批失败并报 `vm.SourceTextModule is not a constructor`，看起来像测试坏了，实际是跑法不对。
- 测试只使用 Node 内置模块与 `tests/fixtures`、`tests/helpers`，无需安装依赖。
- CI 在推送 `main`、Pull Request 和标签构建时先跑全量测试，失败即不打包。
- 安装包与 `git archive` 归档通过 `.gitattributes` 的 `export-ignore` 和打包脚本的排除表剔除测试，仓库本身保留完整基线。

### 静态检查

工具链单独放在 `scripts/lint/`，自带 `package.json` 与 `package-lock.json`，根目录仍然没有 `package.json`。App 运行时和测试依旧不需要 npm 安装任何东西。

```bash
npm --prefix scripts/lint ci --ignore-scripts --no-audit --no-fund
node scripts/lint/node_modules/eslint/bin/eslint.js --config scripts/lint/eslint.config.mjs .
```

- 第一次跑需要网络；之后 `node_modules` 已在本地，直接执行第二条。
- 用 lock 文件安装，顶层和传递依赖都锁住，同一个 lock 在任何机器上拿到同一棵依赖树。不用 `npx`，因为那只能固定顶层版本，剩下的子依赖仍会漂。
- **只查正确性，不查风格**。启用的是未定义变量、重复键、不可达代码、不可靠的 `finally`、异步执行器里直接传 `async` 函数这一类。
- 未使用变量与参数属于 `warning`，不会让门禁失败；`error` 为零是 CI 的前置条件。
- **它抓不到漏掉的 `await`**。浮动 Promise 需要带类型信息的 `no-floating-promises`，本项目不引入那条链路。异步链路的正确性仍然只能靠测试。
- 检查范围只含本仓库自有源码；SDK（`ui/assets/sdk.js`）与 `ui/vendor` 不在范围内。
- 默认不批量 `--fix`。
- `scripts/**` 已被 `.gitattributes` 和打包排除表挡住，所以工具链和它的 `node_modules` 不会进安装包。

### 自动构建与发布

- `main` 推送、Pull Request 和手动 Actions 运行：构建经过官方校验的安装包，保存为 Actions artifact。
- 推送与清单版本一致的标签（例如 `v2.2.0`）：构建成功后自动创建 GitHub Release 并上传安装 ZIP；校验失败不发布，不覆盖已有版本。
- 构建使用固定版本、SHA-256 锁定的官方 Hana 作者工具；只解包工具，不安装或启动 Hana 桌面端。包内携带完整 SDK、解析助手、第三方代码与字体，不含本地会话、凭据、测试或内部文档。
- 本地复现：设置 `HANA_APP_TOOLS_ROOT` 指向含 `scripts/extension-pack.mjs`、`scripts/validate-app.mjs` 的官方 Server 目录，再运行 `node scripts/release-package.mjs --out dist --tag v2.2.0`。
- CI 的打包编排测试与官方静态归档校验，不等同于全功能实机验收。
