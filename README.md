# 分叉对话 (Fork Chat)

分叉对话是运行在 HanaAgent 平台（v2 App）上的二维树状分支对话与思维推导工作台。它将传统的单向线性聊天重构为二维拓扑画布，用于多分支假设验证、多方案推演对比以及复杂推理任务。

---

## 设计理念

传统的对话界面通常采用线性追加模型。当用户希望在某个节点探讨替代方案或测试不同假设时，后续的讨论会混入主上下文，增加长上下文维护的负担。

分叉对话将对话结构建模为二维有向无环图（DAG）：
- **分支解耦**：子节点的发散探索保留在各自独立的分支路径上，不反向影响其他分支。
- **按需汇聚**：需要综合多个维度的结论时，支持从多个父节点收敛生成综合节点。
- **纯白极简界面**：采用纯白背景（`#ffffff`）、浅灰边框（`#e4e4e7`）与深灰文字（`#18181b`），去除非必要的视觉装饰与彩色高亮，聚焦于内容本身的阅读与推导。

## 核心特性

### 1. 2D 拓扑画布
- **自由交互**：支持平移、无限缩放（0.4x ~ 2.2x）、卡片拖拽与视野自适应居中。
- **向右分叉**：点击卡片右侧的锚点即可派生子卡片，通过动态 SVG 贝塞尔曲线建立父子关系。
- **祖先上下文递归**：任意分支触发模型生成时，系统自当前卡片向上递归遍历其父节点路径，按时序组装上下文，保证单条分支具备完整的逻辑链路。
- **多父节点汇聚推导**：支持同时选中两个或多个不同分支的卡片作为共同前置上下文，由模型在聚合节点进行对比、归纳或综合推导。

### 2. 模型推理与流式响应
- **原生打字机流式传输**：基于标准的 ReadableStream 管道实现流式吐字与平滑滚动。
- **模型与推理配置**：通过左侧功能抽屉读取宿主可用模型列表；支持按节点独立指定执行模型及思考深度（Thinking / Reasoning Effort）。
- **心境与结构化标签分离**：模型输出中的 `<mood>`、`<pulse>`、`<reflect>` 等结构化标签会自动归入折叠面板，正文区域保持纯净，后续上下文只引用正文部分。

### 3. Hana 本体会话桥接 (Session Bridge)
为了在保持主会话线性整洁的同时支持复杂问题的离线推导，分叉对话通过公开的会话 SDK 与宿主建立了双向受控桥梁：

- **多入口单向导入**：
  - **消息级**：悬停于宿主聊天消息末尾，点击「送到分叉对话」按钮，直接将该消息作为根节点送入画布。
  - **会话级**：在宿主会话列表右键选择「导入到分叉对话」，App 将提取选定会话的最新上下文。
  - **画布顶部控制**：在画布顶栏点击「连接本体」，可实时观察当前激活会话，浏览其历史或树状条目分支并按需导入。
- **分支树预览与路径选择**：
  - 若导入的目标会话包含分叉或重新生成的历史分支，App 会列出所有叶子分支并提取末尾摘要，由用户明确指定要导入的分支路径。
- **来源引用与回溯**：
  - 导入的卡片标有「本体导入快照」徽标，并持久化保存宿主 `sessionId` 与条目 `entryId`；点击卡片上的「跳回本体」可即时切换并定位回宿主原生会话。
  - 重复导入同一来源节点时具备内容指纹校验与幂等去重，避免生成冗余卡片。
- **安全回传发件箱 (Outbox)**：
  - 在分叉推导获得明确结论后，用户可在卡片上点击「回传」，将推演摘要或整理后的 Markdown 发回原宿主会话。
  - 回传机制采用两阶段确认（Prepare → Confirm），明确展示发送目标与内容，并设置防重发锁与超时保护；不设全自动双向镜像，防止产生死循环或意外消耗模型配额。

## 文档解析架构 (Document Pipeline)

画布支持将本地 PDF、Word（.docx）、Markdown 及纯文本文件作为资料卡片挂载至推导拓扑中。为适配宿主沙盒与底层 RPC 的消息体积约束，文档处理采用分层流式传输方案：

```text
[用户文件]
   ↓ 浏览器切片 (每块 6 MiB)
[App 服务端] → 校验并组合写入私有暂存区 (dataDir)
   ↓ 移交受限文件路径与随机 Capability 令牌
[Node Native Helper] → 独立文件流直传云端/本地解析器
   ↓ 响应结果流式落盘 (ZIP / Markdown)
[主画布] ← 轮询状态并挂载为只读资料卡片
```

- **分块上传与配额控制**：前端在传输大体积文件时采用分片上传，避免单次 JSON-RPC 消息超过宿主通道的体积门限；服务端严格校验块序号、总体积与所有权，合并后原子落盘。
- **独立进程文件流直传**：App 通过正式的 Node Native Runtime 启动受控后台助手进程，直接以底层文件流管道对接解析服务端，规避在应用主线程将整份大文件进行 Base64 编解码所带来的内存膨胀。
- **沙盒与安全防护**：
  - 助手进程通过本地随机端口与主进程通信，每次启动校验私有一过性令牌。
  - 严格限制文件访问边界，解析前对路径执行真实路径检查（Realpath）与符号链接穿透校验，仅允许读取应用数据目录内的普通文件。
  - 外连网络严格遵循 HTTPS 白名单约束，重定向时自动剥离敏感请求头，遇到虚报长度或异常流式中断时即时熔断。

## 状态管理与会话持久化

分叉对话的独立画布数据通过宿主提供的全局存储能力保存在本地应用目录中：

- **并发安全性**：采用同源 Web Locks 机制协同多窗口读写，避免多实例同时打开时产生数据覆盖或覆写冲突。
- **自动保存与容灾**：编辑卡片、拖拽排版或会话切换时自动触发落盘；若推导过程中页面意外关闭，中断的任务会被持久化为“已中断”终态，不会将半截输出误记为成功结论。
- **配额与上限保护**：存储层实施单库最大 100 个会话与 12 MiB 配额限制，触达上限时明确拒绝保存并提示清理，不擅自删除用户的历史对话。

## 安装与开发

### 安装方式
1. 将应用包导入 Hana 桌面端的「扩展管理」；
2. 检查并确认应用所申请的权限（见下文权限清单）；
3. 安装完成后，在左侧导航栏点击 **「分叉对话」** 即可启动。

### 开发与更新
- 修改源码时请在独立工作副本进行；
- 建议通过平台扩展管理入口或执行重载命令更新，避免直接向运行时托管目录复制未验证的文件。

## 权限声明与使用说明

本应用在 `manifest.json` 中声明了以下能力，各项权限均严格限定于对应功能：

| 权限标识 (Capability) | 对应功能用途 | 安全说明 |
|---|---|---|
| `app/models.infer` | 驱动画布卡片的大模型推理与流式输出 | 按用户选定模型发起推导，不自动在后台静默扣额 |
| `app/agents.read` | 读取宿主已配置的助手身份与默认模型 | 仅读取公开元数据，不访问私有提示词实现 |
| `app/sessions.read` | 导入宿主会话历史、条目树与消息快照 | 仅在用户主动导入时读取，剥离思考链与内部私有字段 |
| `app/sessions.manage` | 执行「回传本体」动作 | 仅在用户于回传弹窗二次确认后向指定会话发消息 |
| `app/session.start-turn` | 回传消息后唤醒宿主会话模型生成回答 | 严格由用户在回传选项中明确勾选确认才触发 |
| `app/session.stage-file` | 将推导提取的 Markdown 交付至宿主资料库 | 仅用于显式文件导出，不顺带篡改其他会话附件 |
| `app/runtime.execute` | 启动受控后台助手进程完成文档解析 | 仅启动应用私有目录内的脚本，不调用任意系统程序 |
| `app/runtime.native` | 允许助手以原生 Node 运行时直读大文件流 | 规避主线程 Base64 内存暴涨，严格限制数据目录访问 |
| `app/runtime.network` | 允许助手进程与外部云端解析器通信 | 严格遵循 manifest 声明的官方 HTTPS 域名白名单 |
| `app/ui.clipboard-write` | 画布卡片文本与推导链的一键复制 | 仅由用户点击复制按钮触发 |
