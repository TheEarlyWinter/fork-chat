# 分叉对话 (Fork Chat)

> **打破单向线性聊天。**  
> 基于 HanaAgent (v2 App) 的无限 2D 树状多分支对话与模型推导工作台。支持自由拖拽连线、向右分叉追问、祖先思考链递归继承与打字机流式推理。

---

## 核心设计理念

传统的 AI 对话界面本质上是单向的**一维线性链条（Linear Linked List）**。当你在对话中想针对某一句话做延伸测试、对比不同推导思路，或者想“岔开话题”时，后续的讨论会严重污染主线上下文，试错成本极高。

**分叉对话 (Fork Chat)** 将会话状态重构为 **二维树状分支拓扑（Tree / DAG）**：

- **无限 2D 拓扑画布**：卡片支持任意自由拖拽、平移、缩放（0.4x ~ 2.2x）与视野居中；
- **向右分叉追问（Non-linear Branching）**：点击卡片右侧的 `[+]` 锚点，即可向右分裂出独立的追问卡片，通过动态 SVG 贝塞尔曲线平滑连接；
- **思考链祖先上下文递归继承（Thought-Chain Inheritance）**：在任意子分支中发问，系统自动顺着 `parentId` 向上递归攀爬直至根节点，按时序无损拼装祖先上下文，分支探索绝不反向污染主干；
- **原生打字机流式推理（Typewriter Streaming）**：基于 Web 原生 `ReadableStream` 管道，逐 token 实时打字机吐字与平滑滚动；
- **侧边栏原生模型池（Function Panel Integration）**：深度集成 Hana `fpFullPanel` 原生左侧抽屉，动态枚举宿主当前可用模型，支持跨面板广播即时热切换；
- **纯白极简美学（Pure White Minimalist）**：遵循纯白底色（`#ffffff`）、浅灰微边框（`#e4e4e7`）、炭黑文字（`#18181b`）与等宽字体排版，无多余彩色杂质与 emoji。

## 安装方式

通过 Hana 扩展管理导入应用 ZIP，检查权限并批准安装或更新。在左侧导航打开 **「分叉对话」**；更新后关闭旧页面再重新打开。

开发请修改独立工作副本，再通过正式扩展管理入口更新。不要直接覆盖、软链接到托管安装目录，或以磁盘文件已变更代替运行时验收。

## 依赖与权限声明

本 App 声明了以下 Hana v2 能力：
- `app/models.infer`: 用于调用宿主已配置的底层大模型（如 Gemini、DeepSeek、GPT 等）进行实时推理与流式响应；
- `app/agents.read`: 获取已授权的助手公开资料；
- `app/sessions.read`: 现有会话快照辅助读取能力，不用于本 App 的分叉会话删除；
- `app/ui.clipboard-write`: 支持一键复制分支思考链。

## 流式终态与诊断修复（1.5.2）

- `done.assistant.content` 在没有 `text-delta` 时作为可见正文兜底，只提取 `type: text`，不把 reasoning 或 tool 内容当正文。
- 每个模型事件校验 requestId；身份不匹配、缺少 done、Provider error 和取消仍是失败，不以已有正文伪造成功，也不自动重试。
- 撤回 App 层强制注入的 `reasoningEffort: medium`，不覆盖用户或宿主的推理选择。
- 终态日志只记录 requestId、Provider/model、事件数量/类型、正文与推理字符数、done 标记和错误码，不记录 prompt、正文或隐藏推理内容。

这些改动修复了可离线复现的流协议差异，但不能宣称已解决宿主或 Provider 的真实 `APP_MODEL_PROVIDER_ERROR`；真实错误仍按失败展示。

## 会话右键菜单（1.5.0）

在左侧会话条目上右键，或点击该行的 **⋯**，可执行：

- **重命名**：行内编辑，Enter 保存、Esc 取消，支持中文输入法。标题为 1–80 字符，保存失败保留输入；不会切换画布或停止生成，手动标题不会被自动标题覆盖。
- **删除**：主画布显示会话名及不可撤销提示，需再次点击确认；打开或取消确认不会删除或停止生成。确认后删除当前会话会先取消在途请求并切到其他会话；删掉最后一个时原子创建空白会话。删除非当前会话不打断当前生成。

仅管理 App 自有数据，不修改或删除 Hana 原生聊天。删除无回收站；存储失败或确认后的跨窗口修改会阻止删除。若已保存版本比本窗口记录更新，重新确认会明确提示将删除最新已保存版本及本窗口未保存内容；不会偷偷读取新版本后重试删除。

会话集合格式沿用 1.4.0，无数据迁移或新增权限。改名命令的标题通过宿主 owner-only 存储传递，不广播到共享频道。

## 分叉会话管理（1.4.0）

左侧“会话列表”管理本 App 的独立画布，支持新建、自动保存和切换。每个会话保留分支、消息、草稿、视口及所选助手，重开恢复最后已保存的会话；不与 Hana 原生聊天记录混用。保存失败会阻止切换并显示重试/保存副本入口；进行中的消息恢复为已中断，不作为成功回答继续回传。

数据通过 `hana.storage.global` 由宿主保存，无新增权限。写入需要同源 Web Locks；并发版本冲突不会覆盖其他窗口。当前上限 100 会话 / 12MiB，达到上限明确报错而不删除历史。

**升级提醒：** 旧版本尚未保存的页面内存内容无法自动迁入，请先保留重要旧对话；自动保存从本版本开始。突然退出时以最后确认已保存的快照为恢复边界。

## 心境兼容（1.3.1）

助手回复开头的 `mood`、`pulse`、`reflect` 显式文本块显示在默认收起的“心境 / 沉思”区域，正文单独展示。流式标签不闪入正文，展开状态会保留。原文保留用于排错，后续助手上下文与分支锚点只使用正文；用户输入和代码示例不剥离标签。未闭合块会显示提示，仅有心境而没有回答时明确报告 `EMPTY_BODY`。这是展示层兼容，不关闭或改写助手的人格设置。

## 请求状态与流协议（1.3.0）

- 每次请求有独立 `requestId`，界面区分等待、生成、完成、失败和已停止接收。
- `/api/chat/stream` 返回 `application/x-ndjson`，事件为 `start → text-delta* → done | error | cancelled`；只有收到明确完成确认才进入后续上下文。
- 10 秒无正文显示等待提示；服务端总超时 120 秒，前端 130 秒保护。不自动重试、不隐式切换模型。
- 取消、关闭卡片和离开页面都会尝试停止请求。取消接口按宿主确认的发起方身份隔离，客户端不能自报权限。
- 更新版本后关闭旧页面再重新打开，避免旧 UI 快照继续使用旧流协议。

实际安装/更新请通过 Hana 扩展管理入口导入应用包并确认权限；不要只覆盖已运行应用的文件来判断更新已生效。
